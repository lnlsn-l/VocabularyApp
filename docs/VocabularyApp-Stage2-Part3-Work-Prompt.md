## 3. 已取得的实测证据

- 第一轮 30/30 请求返回翻译，中位耗时 214 ms。
- 第二轮 24/24 请求返回翻译，中位耗时 215 ms。
- substrate→底物，bias→偏见，bandgap→能带，carrier→载体，不适合本项目目标专业语境。
- silicon substrate→硅衬底，bias voltage→偏置电压，band gap→带隙，carrier wave→载波；部分短语能改善语义。
- gate bias→门偏见仍明显不合适，charge carrier→电荷载体仍需要术语修订。

这些证据支持翻译参考，不能保证专业准确率。当前有道接口的词典数据已下线，不承诺词性、全部义项、专业例句或自动消歧。界面不要称其为“权威专业词典”。不要硬编码正确答案、内置此次 30 词词库、静默替换返回结果或用样本修补伪装接口质量。

## 4. 架构与交付顺序

采用：

> 浏览器 → 自己的翻译代理 → 有道官方接口。

个人词库仍保存在浏览器 IndexedDB；新增的服务端只处理主动查询与必要的请求限额，不承担词库云同步或云端主数据库。

实施顺序：

1. 制定小型代理接口与响应模型，核对官方接入和数据使用条款，形成可执行的部署方案。
2. 完成前端和代理核心逻辑、可控响应测试、本地启动方式，先交付可审查实现。
3. 对部署依赖做一次集中交接：具体平台、所需账户/配置、预期费用、限额、密钥配置步骤。
4. 有相关授权和凭据后再完成正式代理与 Pages 联调、验收和版本发布。

不要在开始时因为尚无代理账户就停止写代码。也不要把仅本地运行或模拟接口视为正式线上接入完成。

平台优先评估低运维成本的 serverless 方案，Cloudflare Workers 可作为候选；目前没有确认用户已拥有该平台账户或其网络一定适合用户。核对免费方案是否包含实现所需资源、国内实际可达性和有道上游连接，不承诺“永久免费”。选型只需解释最合适的最小方案，不展开无关平台研究。

本地运行方式应能完成前端与代理联调。服务端处理核心尽量与适配层分开，保持小型模块，不构建大型插件框架。新增依赖仅在确有必要时采用，并说明用途。

## 5. 代理接口与有道调用

建议 `POST /translate`，请求 JSON 仅包含 `{ "query": "silicon substrate" }`。成功返回小型稳定模型，至少含实际 query、来源标识和中文 translations 数组。前端不直接耦合有道完整响应。

代理要求：

- 固定官方 HTTPS 上游，不接受用户传入上游 URL、路径或任意转发头，不能成为通用代理。
- 英译简体中文，使用官方 v3 签名；正确处理短文本、超过 20 字符文本、UTF-8、salt 和 UTC 时间戳。
- 使用通用 NMT，不启用领域化翻译、语音、图片、网页翻译或大模型服务。
- POST 表单请求上游；有道响应仅提取已验证的中文翻译，不将原始响应、签名或发音链接原样透传。
- 请求文本 trim 后 1–200 字符；请求体建议上限 4 KiB，上游响应建议上限 200 KiB，至多展示 20 项翻译。限制集中配置并在报告说明计数口径。
- 上游超时初始 10 秒。前端等待上限要略大于代理总超时，确保能显示代理的明确错误。
- 不自动重试真实计费调用。重复点击、取消和客户端断开应尽量减少多余上游请求；不能承诺取消一定能撤销已计费请求。
- 校验响应结构、有效非空翻译数组及业务错误码；HTTP 200 中的非零 errorCode 也算失败。
- 向前端返回稳定错误类别：无结果、参数错误、服务未配置、网络/超时、限流、额度不足和上游失败。不泄露密钥、请求签名或底层异常详情。
- 日志不记录完整查询、签名、密钥或响应文本；必要诊断仅保留错误类别、耗时和不含个人查询的聚合计数。

## 6. 密钥、部署配置与费用控制

服务端使用独立配置，例如 `YOUDAO_APP_ID`、`YOUDAO_APP_SECRET`。不要把真实值写到 Git、文档、测试夹具、前端状态、localStorage、IndexedDB、URL、命令行参数或构建产物。

`VITE_TRANSLATION_API_BASE_URL` 等前端配置只能保存公开代理地址，不能保存有道密钥或一个被当作私密口令的代理 key。Vite 的前端环境变量不会隐藏秘密。浏览器不能获取服务端密钥来生成签名。

提供不含真实值的配置模板和本地安全配置说明；配置文件进入忽略清单。正式部署使用平台 Secret。让用户在本地或平台控制台输入凭据，不要求粘贴到聊天；不搜索未知位置中的密钥，也不打印既有配置值。

代理配置 CORS 的明确 Origin 白名单，至少涵盖已确认的开发 Origin 与正式 `https://lnlsn-l.github.io`。Pages 的 `/VocabularyApp/` 路径不构成独立 Origin。CORS 不是身份验证或费用防护，不能靠它防止非浏览器滥用。

正式开放前必须有服务端限额和总量保护：

- 按来源进行短时限流、请求长度限制、总量限制及可关闭翻译调用的开关。
- 来源地址只采用平台可信连接信息，不信任任意客户端提供的 `X-Forwarded-For`。
- 可建议全站日最多 5,000 查询字符、月最多 100,000 查询字符作为初始保守限额；这只是技术提议，不是用户已确定的预算或费用保证。
- 多实例环境需要共享且具有明确并发语义的总量计数，超限在调用有道前拒绝。单进程内存计数或非原子的共享计数，不能宣称能严格防止费用超额。
- 计数只保存必要总量和限流标识，不存词库或查询文本；有过期/清理规则。要明确统计成功/失败/超时与预留额度的策略，采用保守方式避免并发穿透。
- 对平台免费配额、计数资源费用、预期个人用量和公开访问用量分别说明。公开应用意味着所有访问者可能消耗站点所有者的有道额度。
- 若需要人机验证或其他防护，先在部署方案解释收益和交互成本；本阶段不默认加入整套用户登录系统。

不替用户充值、购买资源包、开付费套餐、开启自动充值或购买域名。已有授权能覆盖的操作直接执行；新的平台资源或费用需要针对具体可审查方案取得授权。不要为同一授权反复确认。

## 7. 新增词条与查询短语

新增表单必须提供“获取翻译参考”入口。明确区分：

- **英文词条**：最终保存到个人词库的英文。
- **查询词或短语**：本次实际发送给有道的文本。

查询初始使用当前英文词条。允许用户主动调整查询文本，显示实际查询内容和来源；用户没有主动修改查询时，英文变化可以同步查询内容，修改过后应保留其选择并清楚呈现差异，避免查了别的词却误认为当前词的结果。

例如用户希望保存 substrate，可以主动查 silicon substrate，但最终中文“衬底”须由用户修订；不能自动把“硅衬底”裁剪或推断为原词定义，不能将英文词条改成 silicon substrate。

本地无结果入口沿用原有预填流程，允许进入新增表单后查词。普通搜索框键入、筛选、打开词条详情和编辑输入不能自动发起网络调用。

新增入口必做；编辑表单若复用同一组件成本合理，可开放同一功能，必须保护已有释义和备注。若首版只支持新增，文档与界面说明一致，不将编辑支持报告为已实现。

## 8. 翻译结果与采用动作

- 显示“有道翻译参考”、实际查询文本及轻量说明：“专业含义可能不准确，请结合语境修改后保存。”
- 展示真实返回的中文内容。一项就是一项，不生成虚假的词典义项、词性或例句。
- “采用此翻译”只填入可编辑的中文释义框，不提交保存，不修改英文或备注。
- 输入框已有不同的未保存中文时，明确提示将替换，并允许取消；不要静默覆盖用户在请求过程中刚编辑的内容。
- 不把来源、结果或短语自动追加到备注。来源署名和必要链接按条款展示；若许可要求保存或导出时保留信息，先说明兼容做法，不自行绕过。
- 结果按纯文本呈现，不能执行第三方 HTML、脚本或自动加载第三方页面/音频。
- 必须允许用户不查词、忽略候选、手动输入和修订，不能让在线服务成为保存必需条件。

## 9. 状态、异步与输入保护

实现空闲、加载中、有结果、无结果、失败状态，区分代理未配置与网络失败，提供明确恢复路径。

- 同一查询进行中不重复请求；新查询取消旧请求，并用请求标识防止迟到结果覆盖新结果。
- 用户改变查询内容、关闭弹窗或连续保存进入下一条时，旧请求与候选失效。
- 结果抵达不自动填入中文，也不抢焦点、清空表单或触发保存。
- 查询失败、采用取消、保存失败均保留用户输入。重试由用户主动触发。
- 连续新增成功后按既有规则清空词条和查询状态、重置学习状态并聚焦英文；旧词结果不得进入下一条。
- 沿用 compositionstart/end、isComposing 和现有组合输入防护；IME Enter 选词不误触发查询或保存，组合输入期间 Esc 不误关弹窗。
- 查询按钮使用非提交按钮语义；普通 Enter 保留现有表单规则，不引入冲突快捷键。
- 保留 Ctrl/Meta+K 和当前弹窗/输入上下文规则。状态反馈可被辅助技术读取。
- 在 1440px 与 360px 检查长查询、长翻译、滚动和按钮位置；实际手机和真实中文输入法能验证时验证，不能时明确记录边界。

## 10. 本地数据、备份与导入兼容

保持现有词条字段、`VocabularyDB`、Dexie schema 2 和 JSON version 1。在线查询不需要持久化，不为候选结果升级数据库。默认仅内存保存当前查询状态，不加入持久缓存或保存 API key 的设置页。

查询、取消、结果展示、采用到表单、复制和错误恢复不写数据库，不增加 dataRevision/contentRevision 或查看统计。

最终保存继续经 Service / Repository：去除首尾空格、大小写归一化、全库重复检查、数据库唯一约束、业务记录与 metadata 同事务。保存成功/无变化/失败及多标签页规则沿用既有实现。

不能用当前筛选结果为空判断未收录；同名记录不因在线翻译覆盖。新增内容按现有规则计入待备份变化，失败和重复不计入。

保留快照导出、导出期间变化保护、导入只读预览、事务内重新分析、再次确认、查看统计与内容提醒区分等 Part 2 规则。JSON 中只保存用户确认的词条字段，不导出候选缓存、密钥或服务端配置。

不访问或清理同 Origin 其他应用的数据库/存储。新增设置如确有必要，使用 VocabularyApp 专属命名空间，并在报告列出；命名空间减少冲突，不等于安全隔离。

## 12. 测试与验收

复用现有有效测试，为新增行为增加必要测试。自动化 CI 使用可控的代理和上游响应，不持有真实有道密钥，不依赖真实计费接口。真实联调另外记录，不能用 mock 通过证明线上服务可用。

至少覆盖：

| 范围 | 必须验证 |
| --- | --- |
| 本地输入 | 键入、筛选、查看不触发请求；IME 不误查询/提交 |
| 查询文本 | 原词与查询短语分开；实际请求、显示结果和保存字段一致 |
| 采用翻译 | 人工采用，不自动保存；已有中文的替换可取消，备注保留 |
| 错误 | 无结果、超时、离线、HTTP/业务错误、429、欠费、配置缺失、异常 JSON |
| 并发 | A 迟于 B、查询修改、关闭弹窗、连续新增，旧结果不覆盖 |
| 数据保护 | 查询/采用不改变 revision；成功保存一次；失败/重复/无变化符合原语义 |
| 代理安全 | 长度/body/响应限制、固定上游、签名、密钥不透传、文本不执行 |
| 限额 | 未超限成功、超限不调上游、并发接近总量上限不穿透、短时限流、总开关 |
| 密钥 | 测试哨兵服务端秘密不进入前端构建、响应、日志、备份或 Git 跟踪文件 |
| 回归 | CRUD、搜索、筛选、排序、复制、连续新增、查看统计、导入预览、快照与提醒 |
| 兼容 | 旧数据库/旧 JSON 保留，导入后词条可查看、修改、导出 |
| 页面 | 1440px/360px、键盘焦点、长结果、服务不可用时本地流程 |

检查现有 `npm run lint`、`npm test`、`npm run build`、`npm run check:dist`，以及仓库已有开发/生产/Pages 验收流程。新增代理测试纳入可维护的本地/CI 门槛，明确其运行命令。

正式环境验收至少从实际 HTTPS Pages 点击翻译，确认浏览器只联系预期代理、代理实际调用有道、密钥不在客户端、失败提示可恢复、修改并保存后 JSON 往返正常。使用独立 Profile/合成词条，不读取或删除日常词库。

不得取消旧测试的实质保护；对新增联网行为调整准确预期，而不是放开所有第三方请求或忽略控制台错误。保留 Pages 子路径、产物白名单和最小权限配置，代理代码与测试产物不进入 Pages dist。
