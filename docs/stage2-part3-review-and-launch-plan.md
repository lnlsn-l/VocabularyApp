## 3. 正式接入还缺什么

### 3.1 平台账户与真实部署

保留既有 GitHub Pages，新增一个 Cloudflare Workers Free Worker，使用当前 `TranslationQuota` SQLite Durable Object 类和稳定对象名 `VocabularyApp-global-v1`。它仅用于翻译转发与额度计数；个人词库仍在浏览器。

Cloudflare 官方目前支持 Free 计划下的 SQLite Durable Objects。免费平台配额与有道计费是两套约束，Free 超限可能暂停服务，不宜承诺持续可用。见 [Workers 定价](https://developers.cloudflare.com/workers/platform/pricing/) 和 [Durable Objects 定价](https://developers.cloudflare.com/durable-objects/platform/pricing/)。

部署前需用户明确接受这个具体资源方案并完成本机登录。保持 Free，不订购 Paid、域名或中国网络产品。用户所在地到 workers.dev 的可达性和 Worker 到有道的连接尚未实测，先验证再决定是否使用该平台。

### 3.2 有道账户配置与使用范围

用户在本机或平台加密 Secret 中设置 `YOUDAO_APP_ID` 和 `YOUDAO_APP_SECRET`，无需发到聊天。核对通用 NMT 服务状态、实际可用额度，以及当前服务器 IP 限制是否适合 Worker 出口。不要填写 GitHub Pages 的 IP 代替代理出口。

本次取得并阅读了 [有道智云服务条款](https://ai.youdao.com/DOCSIRMA/html/agreement/terms/ydzyfwkt/index.html) 相关段落。第 9.2 节限制部分服务内容/服务数据的缓存、改编和转播；第 9.5 节说明输入、生成内容的权利归属并保留已有权利例外。仅凭这些条款，尚不能确定本应用保存修订释义、JSON 备份是否需要额外标识。这里存在适用范围问题，不能直接断言禁止个人保存，也不能宣称无限制许可。

建议通过有道官方工单澄清下述具体模式，作为公开开放前的账户事项；技术部署准备可并行进行。这是对条款歧义的审慎建议，不是 API 技术认证步骤，也不是已证明必须申请额外许可证。

> 本项目通过通用 NMT API 展示带有道署名和官方链接的临时翻译参考。用户可采用并人工修订后保存为自己的本地词库释义，再通过 JSON 备份和迁移；不批量缓存、不制作词典镜像、不转售结果。请确认这种修订、个人保存和 JSON 导出是否允许，是否需要额外许可，以及保存或导出是否必须保留来源或内容标识。

若回复明确要求持久标识，先制定兼容方案并取得用户确认；不要静默改写备注、移除声明或改变 JSON version 1。现有候选区署名与链接继续保留。

### 3.3 公共访问与消费额度

公开访问者使用翻译时，会消耗站点所有者的有道额度。CORS 白名单只限制正常浏览器的跨站读取，不构成用户身份认证；非浏览器客户端可伪造 Origin。当前全站总量能约束本代理的上游字符量，但无法保证额度只供本人使用。

建议分两档，由用户确认后设置：

| 场景 | 全站每日字符上限 | 全站每月字符上限 | 每来源频率 |
| --- | ---: | ---: | --- |
| 首次真实验收 | 500 | 2,000 | 每自然分钟 10 次 |
| 稳定使用后可选 | 5,000 | 100,000 | 每自然分钟 10 次 |

默认配置目前是正常档，**首次开启前应改为用户接受的验收档**。初验通过也不自动提高限额。

[有道官方价格](https://ai.youdao.com/DOCSIRMA/html/trans/price/wbfy/index.html)目前列出通用常见语种互译 48 元/百万字符：2,000 字符折合约 0.096 元，100,000 字符约 4.8 元。只是单价换算，不是账户账单保证；赠金额度、统计口径、其他应用消费及计费周期以账户为准。当前代理按 UTC 日/月计数，北京时间日切换为 08:00；自然分钟限流不是滑动窗口。失败和预留后取消也占本代理额度，无自动重试。

不用购买资源包即可先检查现有额度。充值、自动充值、付费平台和提高预算均不能由本方案代替用户决定。发生滥用先关闭服务，不以提高额度解决。

## 4. 推荐执行顺序

### A. 完成准备，部署关闭状态的代理

1. 开发对话读取本文件、原开发规范和部署方案，核对实际分支与未提交变更，继续原项目。
2. 用户确认上述一个 Free Worker 与共享 SQLite DO 的具体资源方案，在本机完成 Cloudflare 登录；确认允许少量真实查询消耗已有有道额度和验收档上限。
3. 对当前待部署代码完成已有打包和必要检查。部署 `TRANSLATION_ENABLED=false` 的 Worker，记录实际 HTTPS 地址、Worker version 和绑定。
4. 从用户实际使用的网络访问该地址，向 `/translate` 发出合法、带允许 Origin 的请求，确认返回关闭状态且未触发有道。根地址没有健康检查接口，不能把根路径的 403/404 当作故障。
5. 若域名无法可靠访问，先排查网络/平台；不提前合并网页，也不自动购买域名、换付费计划或添加公共代理。

### B. 低额度真实联调，先验证再合并

1. 用户自行设置两项 Secret、核对账户事项；关闭状态下先确认配置齐备。
2. 将日/月额度改为已确认值，开启服务。确定配置唯一来源，避免下一次 Wrangler 部署把控制台设置覆盖回旧值。
3. 本地应用临时配置真实 HTTPS 代理根地址，并仅临时允许实际使用的开发 Origin，例如 `http://localhost:5173`；以实际端口为准，不使用通配符。
4. 主动执行少量合成查询，例如 `silicon substrate`、`bias voltage`，记录真实状态、耗时和来源，不要求返回固定中文答案。核对浏览器请求只有 query，实际上游为有道，而非测试夹具。
5. 验证采用、已有中文替换确认、人工修订和保存；查询、采用、失败不写词库，最终保存才产生一次正常业务变更。验证取消和修改查询后不会出现旧结果。
6. 用受控方式验证关闭服务后中文手填保存可用；限额和故障边界优先使用已有可控测试，不为触发错误大量消费真实额度。不要删除或重置共享计数。
7. 记录用户实际网络结果。手机网络或另一条网络可作为补充验证；真实手机输入体验不能由 360px 自动截图替代。

### C. 发布 Pages，完成正式验收

1. 删除临时开发 Origin，正式白名单保留 `https://lnlsn-l.github.io`。`/VocabularyApp/` 是路径，不是新的 Origin；命名空间也不能阻止同 Origin 其他页面读存储。
2. 在 GitHub Actions Variables 设置公开的 `VITE_TRANSLATION_API_BASE_URL` 为真实代理 HTTPS 根地址，不附 `/translate`、口令或查询参数。有道 Secret、Cloudflare Token 不进入前端构建。
3. 真实代理联调通过且发布获得授权后，将已验证功能分支合并 main。若合并产生代码变化，完成相应检查；等待 main 的构建和 Pages 部署都成功。
4. 从真实 `https://lnlsn-l.github.io/VocabularyApp/`，使用独立测试 Profile 与合成词条执行下表验收，保留用户日常词库。
5. 全部正式验收通过后创建并推送注释 `v1.2.0`，指向 main 中实际验收的应用提交；先确认标签不存在，不覆盖原标签。如果另有文档提交，说明其与应用提交的关系。

## 5. 正式发布验收标准

| 检查 | 通过条件 |
| --- | --- |
| 真实链路 | 实际 Pages 页面经 HTTPS Worker 查询有道，候选显示实际查询及来源；有少量真实调用证据 |
| 人工确认 | 查询不自动写库；采用只填中文；可以修订；已有中文受替换确认保护；保存才落库 |
| 原词保护 | 查询 `silicon substrate` 时可保存原词 `substrate`，不自动改写英文或裁剪候选 |
| 请求失效 | 取消、改查询、改英文、关闭、连续添加后旧结果不会覆盖当前表单 |
| 错误恢复 | 服务关闭或网络故障时明确提示，手动录词正常；不自动重试 |
| 数据兼容 | 独立 Profile 内 JSON version 1 导出/导入往返正确；原 schema 2 和其他应用存储不受影响 |
| 密钥边界 | 浏览器网络和静态产物只有公开代理地址，没有有道 Secret；不生成含认证信息的验收材料 |
| 消费控制 | 日/月限额、频率、共享持久计数与关闭开关已配置；重部署仍保留同一计数对象 |
| 发布事实 | main CI build/deploy success，线上资产为验收版本；最终 tag 指向实际验收提交 |

测试夹具、历史 30/24 词试查、Wrangler dry-run 和 package 版本号都不能替代真实 Pages 验收。无需再跑一轮 30 词来选择来源。

## 6. 故障处理与交付物

- 真实网络不适用：保持关闭，保留本地录词，记录哪一段失败后再评估平台；不自动改换来源。
- 额度耗尽或滥用：设置 `TRANSLATION_ENABLED=false` 并使配置生效。已在途请求可能已计费；不清空 DO 或复制新代理恢复额度。
- 前端配置错误：修正公开变量并重新构建 Pages；只改变量不会修改已经部署的页面。
- 回滚：保留同一 DO 绑定、对象名和已有计数，保留浏览器词库；不使用删库作为回滚步骤。

新增 `docs/stage2-part3-launch-report.md`，保留原部署前报告作为历史证据。上线报告记录实际日期、公开代理地址、Worker version、授权的限额、主分支应用提交、main Actions run、真实网络与查询结果、关闭/恢复测试、数据往返、最终 tag 和未覆盖设备范围。只记录配置项名称和“已设置”，不记录密钥、Token、签名、真实 IP 或个人备份。

## 7. 用户下一步需要准备

1. 注册或登录 Cloudflare，确认使用 Free；不需要购买服务器或域名。
2. 准备在本机/平台自行输入有道应用 ID 与密钥，确认服务可用和实际剩余额度；无需提供聊天中的值。
3. 决定是否接受公开访问者共享自己的翻译额度；建议先采用 500 字符/日、2,000 字符/月验收档。
4. 向有道核对人工修订、个人保存和 JSON 导出的适用规则。工单可与关闭状态部署准备并行。

这些事项具备后，继续现有开发对话完成 Part 3 B 即可，无需重新初始化或从头开发。后续产品优化等待 1.2.0 真实使用反馈。
